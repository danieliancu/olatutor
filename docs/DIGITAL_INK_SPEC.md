# Digital Ink specification, version 1

Status: implemented in the Python core (`apps/notebooks/ink/`) and the browser core (`static/js/ink/core.js`). Firmware is not implemented. Written in Milestone 0, extended in Milestone 1 with `RESTORE_STROKE` and `DELETE_PAGE`. Machine-readable contract: `contracts/digital_ink/v1/`.

The keywords *must* and *must not* are normative. The shared fixtures decide any disagreement between this text and an implementation; change them together.

## 1. Principles

- Captured strokes are the primary record of a student's work. A raster is always derived, never the source.
- Every platform obeys the same schema, coordinate rules and operation semantics. Rendering code is not shared.
- History for ink is an append-only journal with snapshots. The rest of the SaaS does not use event sourcing.

## 2. Document model

| Concept | Meaning | State in v1 |
|---|---|---|
| Notebook | A set of pages, with its own document journal | Implemented |
| NotebookPage | Declared logical size, orientation and a page journal | Implemented |
| PageRevision | Immutable pin of one journal position, with verified hashes | Implemented |
| InkLayer | `stroke.layer`; v1 allows only `student` | Implemented for that layer; others in `PAGE_SEMANTICS.md` |
| Stroke | An immutable root stroke, made by `ADD_STROKE` | Implemented |
| StrokePoint | `[x, y, t, p]` | Implemented |
| InkOperation | One journal entry | Implemented |
| InkSnapshot | Materialised state at a sequence, used as a cache | Implemented on the server |
| InkCheckpoint | A snapshot chosen as a compaction boundary | Specified only (section 8) |

## 3. Coordinates

- A page has a fixed logical size in **integer units of 0.1 mm**. A4 portrait is 2100 × 2970. The size and orientation are declared by `CREATE_PAGE`.
- The origin is the top-left corner of the page. x grows right and y grows down.
- Screen pixels and notebook units are different things. Each capture computes a matrix from physical device pixels to logical units:

  `x' = a·x + c·y + e`, `y' = b·x + d·y + f`

  built in this order:
  1. Device pixels to CSS pixels, by dividing by the device pixel ratio.
  2. Undo display rotation, for a viewport of W × H CSS pixels:
     - 0°: `(x, y)`
     - 90°: `(y, W − x)`
     - 180°: `(W − x, H − y)`
     - 270°: `(H − y, x)`
  3. Fit the page to the view's width, divide by zoom, and add the scroll position, which is the logical unit at the view origin.
- **The transform runs once, at capture.** Results round half away from zero and clamp to the page. Implementations may differ by ±1 unit here. From then on the stored integers are the truth and everything is exact.
- Each stroke records its matrix (`matrix_micro`, the values × 10⁶), viewport, `dpr_milli` and rotation. `raw_points` may keep physical coordinates for hardware debugging and is otherwise `null`.

## 4. Values and identifiers

- Allowed values: null, boolean, integer within ±(2⁵³ − 1), string, list, map. **Floats are rejected**, even `1.0` when the parser can see it. The JS parser cannot tell `1.0` from `1`, so the server is the authority on the wire.
- Text must be valid Unicode and must not contain U+0000. It is never normalised. Map keys must be ASCII.
- IDs match `^[A-Za-z0-9_-]{1,64}$`, are generated by the client and are **opaque**. Order comes from journal position only, never from an ID or a client clock.

### Points

`[x, y, t, p]`: integers, with `0 ≤ x ≤ page width` and `0 ≤ y ≤ page height`. `t` is milliseconds since the start of the stroke; the first point has `t = 0` and `t` never decreases. `p` is 0–1024 only when the source really senses pressure, otherwise `null`. Pointer Events report 0.5 for a mouse, which must be stored as `null`. Capacitive strength values must not be presented as pressure.

## 5. Canonical encoding and hashes

Hashes run over a tagged binary encoding, not JSON text, so that every language produces identical bytes.

| Value | Bytes |
|---|---|
| null | `00` |
| integer | `01`, then 8 bytes, big-endian two's complement |
| string | `02`, then a 4-byte big-endian byte length, then UTF-8 |
| list | `03`, then a 4-byte count, then the items |
| boolean | `04`, then `00` or `01` |
| map | `05`, then a 4-byte count, then key and value pairs sorted by key bytes |

An optional field is always present with an explicit `null`; a missing field and a null one must not hash the same way. `fixtures/encoding_vectors.json` holds hand-written byte vectors.

Three hashes exist, all SHA-256:

- **Operation chain** (evidence): `H₀ = SHA-256("tutor.ink.v1.chain")`, `Hᵢ = SHA-256(Hᵢ₋₁ ‖ SHA-256(encode(op)))`, over raw 32-byte digests. Only client-authored bytes are hashed, so a client can compute it before any server response.
- **Visible state**: encode `{width, height, strokes}`, where `strokes` are the active pieces in draw order with `{id, z, width, color, points}`.
- **Full state** (convergence): encode `{page_id, width, height, nodes, undo, redo, palm_removed}`, with nodes and palm removals sorted by ID and hidden ones included.

## 6. Operations

Every operation has these fields, all required:

`v` (1), `op_id`, `type`, `page_id`, `writer_id`, `epoch`, `client_seq`, `origin` (`user` or `system`), `client_time_ms` (a claim by the client, or null), `payload`.

| Type | Journal | Payload | State in v1 |
|---|---|---|---|
| `CREATE_PAGE` | document | `width`, `height`, `orientation`, `background` | Implemented |
| `ADD_STROKE` | page | `stroke` | Implemented |
| `REMOVE_STROKE` | page | `stroke_ids`, `reason` | Implemented |
| `ERASE_SEGMENT` | page | `items`, `eraser` | Implemented |
| `UNDO`, `REDO` | page | `target_op_id` | Implemented |
| `RESTORE_STROKE` | page | `stroke_id` | Implemented in the cores; no button in the interface yet |
| `DELETE_PAGE` | document | Empty | Implemented |
| `CHANGE_PAGE` | none | Navigation only: stays on the client, is not hashed and not undoable | Never sent; returns `UNSUPPORTED_OP` if it is |

One gesture is one atomic operation, committed at pointer-up, so sync never exposes half a gesture.

`RESTORE_STROKE` makes a hidden stroke visible again as a new undoable operation, for when history has moved on and undo can no longer reach it. It is rejected if the stroke is already visible (`STROKE_ALREADY_ACTIVE`), if one of its descendants is visible (`ACTIVE_DESCENDANTS`), or if it was removed as a palm contact (`RESTORE_BLOCKED`).

`DELETE_PAGE` hides a page. Its journal and revisions stay on the server, a deleted ID cannot be reused, and further ink is refused (`PAGE_DELETED`) and quarantined. A client must send a page's unsent ink before its deletion.

## 7. Partial erasing

A root stroke's points never change. Each piece of ink is a **node**: an inclusive range `[start, end]` of its root's points, with `root_id` and `parent_id` recording lineage.

An `ERASE_SEGMENT` item names an active parent and lists children. Each child range:

- indexes the **root's** points, not the parent's, and lies inside the parent's range;
- is ascending and disjoint from its siblings. Adjacent ranges are allowed, which is how a stroke splits between two vertices when the eraser crosses a segment with no vertex inside it.

Further rules:

- Zero children means the parent is entirely removed. One child equal to the parent's whole range is rejected as `ERASE_NOOP`. A one-point child is valid.
- Children keep the original timing and pressure, inherit style from the root and the z-position of their parent.
- **The stored result is authoritative.** Replay never re-runs geometry. `eraser.path` and `radius` are for audit only.
- v1 never interpolates points. Dropping a tiny fragment is client policy, applied at erase time and recorded by leaving it out.

Known effect: because ranges cut at vertices, erasing on sparsely sampled ink removes up to the neighbouring vertex and can look wider than the eraser. A later version may add stored, flagged synthetic end caps. Whether this matters on real hardware is unmeasured.

## 8. Undo, redo, snapshots and revisions

- Each page has a LIFO undo stack and redo stack, always derived from the journal and never from client memory.
- `UNDO` and `REDO` must target the top of their stack, else `NOT_STACK_TOP`. They are not themselves undoable. A new content operation clears redo.
- Undoing an erase reactivates the parents and hides the children. Redo reuses the same child IDs.
- A snapshot records roots, nodes, effects, stacks, operation index, palm removals and chain hash, including hidden ink. **Replay from a snapshot must equal replay from zero.** The server only trusts a snapshot if it reaches the page's chain hash, and otherwise rebuilds from zero and logs an error.
- A `PageRevision` pins `(page, seq, visible hash, full hash, chain hash)`. The server creates it only if its own replay reproduces the client's hashes.
- Operations with a journal position below the pin must not be undone (`PINNED`). New ink after a revision is allowed and leaves the pinned evidence unchanged, because reconstruction at that `seq` ignores later operations. Multi-page submissions will pin a manifest of revisions in a later milestone.
- **Compaction (specified, not implemented):** an InkCheckpoint is a verified snapshot that older journal entries may be folded into. Compaction must never delete a range covered by a pin.
- **Erasure (specified, not implemented):** stroke payloads will be separately deletable, leaving an "erased" marker so that verifiers report *erased* rather than *corrupt*. Hidden ink persists until then, which must be disclosed to parents. Whether residual hashes are personal data is an open legal question, see `SECURITY_PRIVACY.md`.

## 9. Validation order and error codes

Checks run in this fixed order, so that all implementations report the same code:

1. Value scan: `FLOAT_NOT_ALLOWED`, `INT_OUT_OF_RANGE`, `INVALID_STRING`
2. `UNKNOWN_VERSION`
3. `UNSUPPORTED_OP`
4. Structure: `INVALID_SHAPE`
5. Journal and page: `WRONG_JOURNAL`, `WRONG_PAGE`, `DUPLICATE_OP`
6. Semantics:
   - Strokes: `DUPLICATE_STROKE`, `UNKNOWN_STROKE`, `STROKE_NOT_ACTIVE`, `POINT_OUT_OF_PAGE`, `INVALID_TIMING`
   - Erasing: `INVALID_RANGE`, `ERASE_NOOP`
   - History: `NOT_STACK_TOP`, `PINNED`
   - Origin: `INVALID_ORIGIN`, `SYSTEM_REMOVE_INVALID`
   - Restoring: `STROKE_ALREADY_ACTIVE`, `ACTIVE_DESCENDANTS`, `RESTORE_BLOCKED`
   - Document journal: `DUPLICATE_PAGE`, `INVALID_PAGE`, `UNKNOWN_PAGE`, `PAGE_DELETED`

A rejected operation must leave state unchanged.

## 10. Synchronisation

A batch is `{writer_id, epoch, base_seq, ops}` with 1–200 operations of one writer epoch, applied entirely or not at all.

- **Writer position:** `client_seq` is contiguous per writer, epoch and journal, and the server only accepts the next one (`SEQUENCE_GAP` returns the expected value). A client starts a new epoch each session, and reinstalling gets a new `writer_id`.
- **Idempotency:** `op_id` is the idempotency key. A retry with the same content returns the original `seq`, which also covers lost acknowledgements. The same key with different content is rejected (`IDEMPOTENCY_MISMATCH`) and quarantined.
- **Conflict policy for ink:** a page has one linear history. `base_seq` is the writer's view of the server head, and must satisfy `base_seq + retried operations = head`. Otherwise the result is `BASE_CONFLICT`: the batch is quarantined, and nothing is merged automatically. The user then chooses to keep their version as a new page (a copy of what they saw, without its history) or to use the other version. Work set aside either way stays on the device. This explicit policy replaces the server-issued lease first considered, which would have added nothing to safety. See ADR 0004.
- **The document journal is multi-writer:** page lifecycle operations have unique IDs and commute, so `base_seq` is not checked there. Its order is the server's arrival order, so clients do not compute a document chain hash.
- **Contract violations** return 422 and are quarantined. Quarantined work is never evidence until explicitly promoted (no promotion UI exists yet).
- **Clocks:** `client_time_ms` is a labelled claim, stored beside the server's receipt time and never used for ordering.
- **Client behaviour:** each operation is written to IndexedDB before it is sent. Retries use bounded exponential backoff: 5 retries, then "paused" with a visible retry button. A conflict stops sending and keeps the work locally. The sync state is always visible.

Browser storage limits: IndexedDB can be evicted by the browser or cleared by the user, and it is not a guarantee. The local journal currently grows without a limit.

Known limits: two open tabs of one notebook are treated as competing sessions, and the later one to write receives a conflict. Other devices' new pages appear only after a reload.

A service worker lets an already visited notebook reopen without a network. It caches only the page and static files, never ink, and needs a secure origin: on a plain-HTTP LAN address it is unavailable, and the page says nothing about it beyond a console warning.

## 11. Cancelled strokes and palm reclassification

The palm rejection engine itself is Milestone 2. The contract rules are:

- A stroke cancelled before commit is **never journaled** (data minimisation). Only aggregate counters may be kept.
- A client should hold back commit until classification settles.
- Late reclassification is `REMOVE_STROKE` with `origin: system` and `reason: palm`, for a single root stroke. It stays off the undo stack and removes the stroke's `ADD_STROKE` from it. It is rejected if the stroke was split, if any other operation on either stack touches it, or at or below a pin.

The browser prototype only ignores touch contacts while a pen is in use, or for 1.5 s after. That is a placeholder, not palm rejection.

## 12. Conformance

An implementation conforms when it passes, with no changes to the fixtures:

| Fixture | Proves |
|---|---|
| `encoding_vectors.json` | Encoding bytes and SHA-256 vectors, hand-written |
| `replay.json` | Geometry and stacks, written by hand; hashes computed by the Python core |
| `reject.json` | Must-reject inputs and their exact codes |
| `random.json` | Seeded random journals, with expected results from the Python core |
| `transforms.json` | Hand-computed coordinate cases, ±1 unit |
| `document.json` | Page lifecycle: created, deleted and refused cases |

Property tests: a snapshot at any point equals replay from zero; `undo^n redo^n` restores the visible page; snapshots survive a JSON round trip; ranges stay inside their root; encoding ignores map insertion order. `scripts/generate_ink_fixtures.py` regenerates the computed parts and fails if the hand-written geometry disagrees.
